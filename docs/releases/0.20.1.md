# AI Project Studio 0.20.1

**Unsigned prerelease, not production-qualified.** Windows may show an
unknown-publisher or SmartScreen warning. macOS installers are ad-hoc signed,
not notarized; Gatekeeper may require explicit approval. No automatic-update
feed is published. Back up important workspace data before trying this release.

## Review Board and persistent Agency workers

- Recover missing immutable Git target objects needed to prepare a review.
- Maintain the saved warm-worker target using provider-owned persistent ACP
  processes for Copilot and Agency, rather than launching Agency on demand.
- Initialize native sessions before marking workers idle, preserve context
  isolation, and apply concrete review models before dispatch.
- Use every available warm review worker, including manifest-backed reviews.
  Reviews requested during startup queue at the configured capacity instead
  of locking the whole review to its first ready worker.
- Retry failed review steps up to five times by default, retire unhealthy
  workers, and switch retries to other workers while preserving the overall
  review deadline and completed perspectives.
- Keep review workers tool-free. Native authentication and process admission
  can block readiness; exhausted retries remain explicit failures.
- Stop Agency descendant processes before disposing their parent on Windows.

## CLI startup, Planner and Explorer

- Enable installed CLI choices when opening the app and preserve safe provider
  switching.
- Keep planned tasks available while users answer native CLI setup questions,
  instead of dispatching work into a blocked terminal. Studio does not answer
  authentication or permission prompts on the user's behalf.
- Show animated loading overlays while Explorer/workspace views initialize
  and restore terminal geometry after setup input.

## MCP, updates and closing

- Resolve Windows npm/npx MCP launchers without a shell.
- Allow manual update checks in source builds, surface retryable failures,
  and use the repository's public release feed when GitHub API checks are
  rate-limited. Guided updates do not bypass installer trust checks.
- Confirm closing with the app's branded icon and an explanation of what will
  stop. **Keep open** is the safe default and leaves ongoing work untouched.
  Accepted closes retain cooperative backend cleanup; verified update and
  relaunch shutdowns do not ask again.

## Release evidence and limitations

Local validation passed the build/typecheck, backend and UI coverage gates,
and 280 desktop harness tests. Native Agency initialization, model selection,
idle persistence and process exit were checked without dispatching an AI
prompt. The running development app reported ten configured workers, all ten
initialized and idle.

These checks are not evidence that a real Review Board inference completed
end-to-end. CLI authentication, provider outages and admission limits can
still prevent execution or exhaust bounded retries.

The existing release workflow gates the exact tagged commit on Windows, Linux,
Apple Silicon macOS and Intel macOS before building Windows x64 and macOS
arm64/x64 installers. Published candidate manifests bind installer hashes to
that commit and workflow run. Signing, notarization and production qualification
remain separate; this prerelease is not marked latest or promoted to stable.
