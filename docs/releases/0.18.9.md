# AI Project Studio 0.18.9

**Unsigned prerelease.** These installers are not production-qualified. Windows
may show an unknown-publisher or SmartScreen warning. The macOS build is
**ad-hoc signed but not notarized** (no Apple Developer ID yet); Gatekeeper still
gates it behind the quarantine prompt. No automatic-update feed is published.

> **macOS: "AI Project Studio is damaged and can't be opened"?**
> That message appears when macOS quarantines a downloaded app it can't verify.
> After dragging the app to `/Applications`, clear the quarantine flag once:
>
> ```bash
> xattr -dr com.apple.quarantine "/Applications/AI Project Studio.app"
> ```
>
> Then open it normally. This build is ad-hoc signed, so Apple Silicon no longer
> reports it as "damaged" — you'll get the standard "unidentified developer"
> prompt instead, which the command above resolves.

This patch prepares the release pipeline to **code-sign installers for free where
possible**, without changing today's unsigned/ad-hoc downloads.

- **Windows signing via SignPath Foundation (free, OSS)**: the release workflow
  can now sign the Windows `.exe` through the free
  [SignPath Foundation](https://signpath.org/) open-source program. When the
  SignPath secrets are configured, the built installer is signed in SignPath's
  managed workflow (the private key never touches CI) and the signed binary is
  what gets hash-verified and published. Until then, Windows downloads remain
  unsigned exactly as before.
- **macOS Developer ID + notarization (optional, paid)**: the workflow now also
  supports full Apple Developer ID signing and notarization, which removes the
  Gatekeeper prompt. It activates only when a paid Apple Developer ID is
  configured; the free default stays the ad-hoc signature, so nothing changes for
  this prerelease.
- **Fail-closed and non-disruptive**: both signing paths are opt-in and skip
  entirely when their credentials are absent, so this build is produced by the
  same free unsigned/ad-hoc path as 0.18.8. Setup for both is documented in
  `docs/development.md` (Code signing).

Everything from 0.18.8 (and 0.18.7) is retained: multi-CLI provider support
(GitHub Copilot + Agency) with a network-aware default and a generalized
first-run install gate, automatic Node.js/Git/gh provisioning on first launch,
the macOS "damaged" packaging fix, the deterministic release pipeline, the
Team-tab time-in-review sort, the right-click tab menu, the smoother Windows
auto-update, and the Agency CLI update notice.

The release workflow independently gates the exact release commit on Windows,
Linux, and macOS. Backend and UI coverage remain at 100%; the desktop harness
regression suite passes. Coverage thresholds and timeouts are unchanged.

The known limitations documented for 0.18.0 still apply. Back up important
workspace data before trying this prerelease. Installer provenance manifests
retain their unqualified status.
