# AI Project Studio 0.11.5

**Unsigned prerelease.** These installers are not production-qualified. Windows may show an unknown-publisher or SmartScreen warning. The macOS build is unsigned and not notarized; Gatekeeper may block it. Version 0.10.3 remains the stable release. No automatic-update feed is published for this prerelease.

This release is almost entirely about stability. Most of the failures reported against 0.11.x — the Skills page never loading, review-board perspectives failing, requests timing out in the explorer, the app being impossible to close — turned out to share a single root cause: the backend could die, and nothing brought it back or even told you it had gone.

## Fixes (stability)

- **The backend no longer dies from a single stray fault.** An unhandled promise rejection or uncaught exception terminated the whole backend process, and nothing restarted it. Every open page then failed at once, which is why unrelated features appeared to break together. Such a fault is now logged and the backend keeps serving.
- **A crashed backend is restarted automatically.** The desktop shell previously left a dead window open against a backend that was gone. It now supervises the backend and restarts it with backoff. If the restarts are exhausted, the app says so plainly and offers to restart the app rather than failing silently.
- **The app can always be closed.** Closing was blocked whenever backend shutdown could not be confirmed — but a backend that was hung rather than crashed never reported an outcome at all, so the block could never be lifted and the app trapped you. You are now offered a force close, which never claims a clean shutdown it did not observe.
- **Pages no longer hang forever on loading skeletons.** Requests were bounded only until the response headers arrived, so a backend that died midway through a reply left the read waiting indefinitely: no data, no error, no way to retry. The whole read is now bounded. This is the direct cause of the Skills page stuck on placeholder rows.
- **Every internal server error now records its real cause.** Unexpected failures were flattened into a generic 500 with the original error discarded, leaving nothing to diagnose. The underlying fault is now logged with the request that triggered it.
- **The warm-pool endpoints report the process budget consistently**, so the Settings page can no longer show a pool state that disagrees with the backend.

## Fixes

- **The saved warm-pool size is shown instead of the one the backend booted with.** The Settings field read the boot snapshot, which never moves when a new value is saved, so every edit appeared to revert on reload even though it had been stored correctly.
- **Feature usage refreshes as work is recorded.** The usage view had regressed to a manual snapshot, so the page sat frozen and the refresh button appeared broken.
- **A rejected feature move now explains itself.** Moving a feature into a sub-category could be refused by the backend — for example when the destination sits inside the folder being moved — but the refusal was discarded. The tree simply snapped back with no message, which read as drag-and-drop not working.

## New

- **Move a feature folder without dragging.** Each feature row has a move action that lists every valid destination, including deeply nested ones that were awkward or impossible to reach by dragging. Destinations inside the folder being moved are left out, because they cannot be valid.
- **A stopped backend is visible in the UI**, with a restart action, instead of leaving pages to fail one by one with no explanation.

## Known limitations

- Long-duration soak, restart and process-count runs have not been completed for this release. The soak harness added here exercises health and warm-pool endpoints only; it does not yet cover per-feature endpoints under realistic concurrent work, so it should not be read as sustained real-load qualification.
- The specific fault behind the review-board perspective failures has not been reproduced and identified. The conditions that caused it are addressed above and the cause is now logged if it recurs, but it is not confirmed fixed.
- A separate leak (orphaned provider CLI session processes not being reconciled after a backend restart or crash) is still tracked as part of an active, larger session-reconciliation effort.
- Keeping the process alive after an uncaught fault trades a possible inconsistent state for not losing warm metasessions and in-flight work. This is a deliberate choice and it is not free.
- Full packaged/native, upgrade/restore, and supported-platform qualification is not complete. Signing is intentionally omitted from this prerelease.
- Automatic retained-image cleanup is unavailable; deletion is manual because provider-history references cannot be proven absent.
- Automatic installation remains withdrawn in favor of guided release-page installation.

Back up important workspace data before trying this prerelease. Installer provenance manifests are included; their pending qualification status remains accurate after publication.
